# Controlled travel regression authorization

The growth gateway requires a real account session or a server-issued guest cookie, trusted origin, and durable quota admission before any paid provider work. Older planning/calendar/provider regressions import route handlers directly in Node, without a Next cookie context or a live quota database. Their original calls now stop at the new authorization boundary instead of reaching the travel behavior they are intended to check.

`scripts/fixtures/admitted-travel-routes.ts` bundles the actual production handlers with exactly one replacement: `src/lib/growth/trial.ts` admits an authorized account, releases reservations locally, and allows map lookup work. It does not replace itinerary generation, message validation, intent routing, requirements/date parsing, repair logic, provider clients, snapshot stripping, or failure handling. Each existing test retains its original HTTP fixtures and travel assertions. This explicitly models the signed-in path, including the existing ten-day and multi-city constraints; it does not redefine the bounded guest trial.

The wrapper is used by trip routing, trip calendar, map provider, photo screening, Chinese website and the six Shanghai route regressions (generation, bounded repair, quality, meal categories, dining, attempt three). Their assertion values have not been reduced or removed. Separately, `scripts/verify-trial-api.ts` bundles the real admission/gateway/account-session code and verifies actual authorization, origin, missing configuration, trusted IP, emergency stop, quota denial/storage failure, provider ordering, guest canonical continuation, unsupported scope and persistence failure. Only its paid providers, cookie/session transport and RPC transport are controlled. `scripts/verify-trial.ts` tests quota SQL and isolation in PostgreSQL. The authorized wrapper cannot substitute for these gateway tests.

The calendar regression replays its documented 2026-10-11 scenario with a local clock inside the bundled handler: “start from 20 oct” must still mean 2026-10-20. Without that controlled clock, running after October 20 changes an implicit future date to 2027 and makes the original fixture nondeterministic. The application date parser and all original 2026 assertions stay intact; the clock override is confined to this controlled replay and does not modify global Date or other tests.

These checks provide deterministic regression evidence. They do not prove live provider coverage, real-account persistence, deployed quotas, venue facts, traveller value or Product Human Gate approval.

Actual model transports now also require an AsyncLocalStorage admission context and a per-child-call database allowance. Direct model/provider fixtures run under explicit controlledTravel(main); bundled route fixtures substitute only this budget dependency together with the outer admission. All transport fixtures/assertions remain unchanged. verify-model-budget independently executes the actual child-call quota SQL and verifies no-context/denied vision calls precede network transport.
